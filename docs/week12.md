# 12주차: 최소 단계 관문

**E1·E3가 명령 하나로 5회 반복 실행된다.** 이번 주 말이 최소 단계 관문이다. 일정이 밀려도 여기까지 되면 보고서가 성립한다 (`docs/plan.md` 8절).

- [ ] E1 서버 설정 확정 (아래 제안)
- [ ] 실행기가 서버·컨트롤러와 연결되어 E1(C0 1·8·32·64, C1, C2)이 5회 반복된다
- [ ] E3: 같은 컨트롤러 에이전트 2개, 그중 하나는 늦게 합류
- [ ] E1·E3 결과 그래프 (평균 ± 표준편차, Jain 지수)
- [ ] 최소 단계 보고서 초안 (`reports/`)

## E1 서버 설정 제안

예시 설정(`examples/config.json`)은 적정 동시성이 약 1개라 컨트롤러 차이가 드러나지 않는다. 아래 설정에서 C2 톱니를 확인했다.

| 설정 | 예시 | 제안 | 이유 |
| --- | --- | --- | --- |
| `output_token_seconds` | 0.002 | 0.02 | 지연을 약 0.8초로 늘려 적정 동시성을 약 8로 |
| `slots` / `queue_size` | 4 / 16 | 64 / 64 | E1은 한도가 병목이어야 한다 (슬롯 병목은 E5) |
| `capacity` | 20 | 3 | 처음 버스트가 슬로 스타트를 왜곡하지 않게 |
| `refill_rate` | 10 | 10 | 그대로 (초당 10건) |

## 주말 점검 회의 안건

1. E1·E3가 명령 하나로 5회 반복되는가
2. 결과에서 C0·C1·C2의 차이를 TCP 개념으로 설명할 수 있는가
3. 못 미치면 13주차 범위 조정 (예: E4·E5 축소, E3를 에이전트 2개로 유지)
4. 13주차 분담 확인 (C3, E2, E4, `/admin/config`)

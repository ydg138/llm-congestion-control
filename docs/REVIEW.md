## 2026-11-16 실험 로그와 팀 컨트롤러 연동

Windows에서 전체 테스트 57개가 통과했습니다. 신규 테스트는 에이전트별 재시도 집계, 잘못된 식별자, 과부하·취소 처리, 대기열·버킷 CSV, 정상 종료 직전 변경과 재시작 후 기록 분리를 확인합니다.

C0-8·C1·C2 각각 실제 HTTP 200 → 429 → 422를 받았고, C2의 윈도는 1에서 시작해 2 → 1 → 1로 변했습니다. 세 경우 모두 마지막 in_flight는 0, 서버의 해당 에이전트 누계는 완료 1건·429 1회였습니다. 당시에는 P3 반복 실험과 실제 모델 측정 전이었습니다. 이후 E1·E3 반복 실험과 E6 기본 측정이 완료됐으며, 현재 상태는 문서 상단의 2026-11-26 기록을 참조합니다.

## 2026-11-10 검증 범위

개발 환경 Windows / Python3.11.2 / aiohttp3.14.5. 기본 서버·계산 모델·동시 요청·취소·3종 한도·설정 변경·시나리오·측정 도구의 52개 테스트 통과 후, 별도 프로세스 CLI 파이프라인 테스트 1개도 통과했습니다(총 53개). 측정 도구 테스트의 Ollama 응답은 합성 HTTP fixture이며 실제 모델 실험이 아닙니다.

별도 프로세스 검증에서 JSON 설정 파일과 시나리오를 읽고 동시성 1·2의 실제 HTTP 요청으로 모의 측정 CSV/실행 메타데이터를 생성했습니다. 비교 JSON CLI는 합성 real CSV로 형식·계산을 검증했으며 실제 LLM 비교 결과로 사용하지 않습니다. 기본 smoke 검증도 API2.0의 출력량·TTFT·정산·422까지 포함해 통과했습니다.

전달 ZIP을 별도 폴더에 추출하고 새로운 가상환경에 고정 의존성을 설치한 뒤 **53개 전체 테스트와 독립 프로세스 smoke 검증이 모두 통과**했습니다. 실행 중인 8000번 서버도 API2.0으로 갱신하고 실제 HTTP200·출력32토큰·prefill/decode/TTFT 응답을 확인했습니다.

`python -m unittest discover -s tests -v`로 재현합니다. `scripts/smoke_test.py`는 별도 서버 프로세스와 표준 HTTP 클라이언트로 API·길이·토큰정산·429/회복·422·재시작을 확인합니다. 기존 8000번 서버는 건드리지 않습니다.

## 모델의 의도와 한계

- 서버 입장 시 max_output_tokens를 예약하고 실제량과 정산하는 정책은 과제용 상한 예약 모델입니다. 특정 상용 제공자의 과금 정책과 동일하다고 주장하지 않습니다.
- 출력 길이를 서버가 결정해도 클라이언트에는 완료 후 제공합니다. 동일 작업·시드·범위·상한을 유지해야 비교 조건이 같습니다.
- 서비스는 non-streaming JSON입니다. 내부 TTFT는 실제 클라이언트 스트림 TTFT와 측정 위치가 달라 비교 도구가 직접 상대 오차를 계산하지 않습니다.
- 전송/스케줄링 지연 때문에 같은 설정의 실시간 실험 결과가 완전히 동일하지 않습니다. 핵심 계산 테스트는 가상 시각, 큐 테스트는 Event를 이용해 검증합니다.
- 상태는 한 프로세스에 존재합니다. P3 실행기와의 연동·반복 실행은 검증됐습니다. 다른 물리 PC 사이의 방화벽/LAN 및 macOS/Linux 실행은 이 기록에서 검증 완료로 주장하지 않습니다.
- E1·E3 반복 실행과 E4 정식 실행, E6 기본 실측은 완료됐습니다. 긴 입력 측정에 따른 계수 보정, 실제 중계 서버 검증과 분석·발표 정리가 남아 있습니다. 서버 코드 구현을 팀 프로젝트 전체 완료로 해석하지 않습니다.

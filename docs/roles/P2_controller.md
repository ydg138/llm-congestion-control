# P2 컨트롤러: 양동규 (팀장)

에이전트가 요청을 언제, 몇 개나 보낼지 정하는 컨트롤러 C0~C5를 만든다. 이 프로젝트에서 4주차 TCP 혼잡 제어가 가장 직접 드러나는 파트다. 팀장으로서 매주 PR 리뷰 순서와 주간 보고서 제출도 챙긴다.

## 내가 맡는 파일

- `client/controllers.py`: 컨트롤러 C0~C5 (순수 로직, asyncio·HTTP 없음)
- `client/factory.py`: 이름(`"C2"` 등)과 매개변수로 컨트롤러를 만드는 함수
- `tests/test_controllers.py`

## 발표 때 설명할 수 있어야 하는 것

- **왜 성공마다 1/cwnd씩 늘리나**: 한 바퀴(윈도 하나만큼의 응답)에 정확히 1이 늘게 하려고
- **429가 동시에 10개 오면 10번 줄이나**: 아니다. 줄이기 전에 보낸 요청의 429는 같은 혼잡으로 본다. TCP가 한 윈도 안의 여러 손실을 한 번으로 보는 것과 같다
- **AIMD가 왜 공정해지나** (Chiu & Jain): 덧셈 증가는 모두 같은 양씩 늘리고, 곱셈 감소는 큰 쪽이 더 많이 줄어서 몫이 같아지는 쪽으로 모인다
- **지수 백오프(C1)와 AIMD(C2)의 차이**: 백오프는 기다리는 시간만 늘리고 동시 요청 수는 그대로다. AIMD는 보내는 양 자체를 맞춘다
- **긴 답이 늦은 것과 혼잡을 어떻게 구분하나**: 전체 응답 시간 대신 TTFT나 토큰당 시간을 본다
- **429와 529에 다르게 반응해야 하나**: 429는 나만 줄이면 되고 529는 모두가 줄여야 한다. TCP 손실에는 이런 구분이 없다

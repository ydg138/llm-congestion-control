# P3 실험: 박준영

작업량을 만들고, 에이전트를 돌리고, 조건별로 반복해서 기록하는 실험 실행기를 만든다. 실험 E1~E6를 실제로 돌리는 사람이다. "스크립트 한 번으로 실행 → CSV"가 되게 만드는 게 목표다.

## 내가 맡는 파일

- `runner/workload.py`: 시드 고정 작업 생성
- `runner/agent.py`: 비동기 에이전트 (컨트롤러 + aiohttp)
- `runner/run.py`: 명령줄 실행기, 요청 로그 CSV 저장
- `runner/experiments.py`: E1~E6 조건 정의
- `runner/real_adapter.py`: 로컬 LLM 서버·실제 API용 어댑터 (14주차)

## 주차별 할 일

### 10주차 (11/2 주): 가장 작은 실행기
- [ ] 작업 N개 생성 (입력 토큰, 최대 출력 토큰), 시드 고정
- [ ] 에이전트: 컨트롤러의 `can_send`가 참일 때만 보내고, 응답에 따라 `on_success`·`on_rate_limited` 호출, 429면 컨트롤러가 정한 만큼 기다렸다 재시도
- [ ] 요청 로그 CSV 저장
- [ ] 컨트롤러가 아직 없으면 같은 인터페이스의 임시 컨트롤러로 먼저 테스트
- **완료 기준**: 에이전트 1개가 작업 100개를 끝내고 CSV가 남는다
- **같이 할 일**: 주 후반에 P1·P2와 연결 확인

- [ ] 실제 헤더 이름을 우리 이름으로 바꿔 주는 `real_adapter.py`
- **완료 기준**: 가짜 서버와 실제 서버의 지연 곡선 비교 데이터가 있다

## 발표 때 설명할 수 있어야 하는 것

- **왜 시드를 고정하나**: 모든 컨트롤러가 똑같은 작업을 받아야 차이가 컨트롤러에서 온 것이라고 말할 수 있다
- **왜 5회 반복하나**: 비동기 실행과 무작위 지터 때문에 결과가 조금씩 다르다. 평균과 표준편차를 같이 봐야 우연이 아닌지 안다
- **에이전트의 동작 순서**: 윈도에 여유가 있으면 보냄 → 응답이 오면 컨트롤러에 알림 → 429면 기다렸다 재시도 → 모든 작업이 끝날 때까지 반복
- **E2·E4·E5가 각각 무엇을 보려는 실험인가** (`docs/plan.md` 5절)
- **가짜 서버 결과를 믿어도 되나**: E6에서 실제 서버와 비교한 결과로 답한다
- 예상 질문: "실제 API로 다 하면 안 되나?" → 비용, 같은 조건 반복이 불가능, 한도를 마음대로 바꿀 수 없음
